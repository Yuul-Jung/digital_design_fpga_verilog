## 학습 안내

**잘 시작하면 반은 끝난 것입니다.** 이 장에서는 Ubuntu(우분투) 24.04에 AMD Vivado(비바도, FPGA 설계 도구) 2024.2를 설치하고, Basys3 보드를 PC에서 인식시킨 뒤, 스위치 하나로 LED 하나를 켜는 첫 회로까지 완성합니다.

| 항목 | 내용 |
|---|---|
| 보드 | Digilent Basys3 (AMD Artix-7 `XC7A35T-1CPG236C`) |
| 설계 도구 | Vivado 2024.2 ML Standard |
| 편집기 | VS Code |
| 운영체제 | Ubuntu 24.04 |
| 완료 기준 | `djtgcfg enum`에서 Basys3 인식, SW0으로 LED0 ON/OFF |

**전체 흐름**

1. 시스템 업데이트와 필수 패키지 설치
2. Vivado 설치와 환경 변수 등록
3. 케이블 드라이버·Digilent Adept Runtime 설치, 사용자 권한 설정
4. 작업 폴더 준비와 VS Code 연동
5. Basys3 하드웨어와 XDC(핀 제약 파일) 이해
6. SW0 → LED0 첫 실습

> **준비물:** Basys3 보드와 **데이터 통신이 되는** Micro USB 케이블. 충전 전용 케이블로는 보드가 인식되지 않습니다.

## 드라이버와 보드 인식

PC와 Basys3는 두 단계의 소프트웨어를 거쳐 연결됩니다.

```text
PC (Vivado)
   ↓
Digilent Adept Runtime (USB 드라이버)
   ↓
USB 케이블 (전원 + 데이터)
   ↓
Basys3 FPGA
```

**① Vivado 케이블 드라이버**

```bash
# Vivado에 포함된 케이블 드라이버 설치
cd /tools/Xilinx/Vivado/2024.2/data/xicom/cable_drivers/lin64/install_script/install_drivers
sudo ./install_drivers
```

**② Digilent Adept Runtime / Utilities**

Vivado에는 Digilent 보드용 USB 드라이버가 들어 있지 않습니다. Adept Runtime이 없으면 Hardware Manager의 **Open Target**이 동작하지 않고 `djtgcfg` 명령도 사용할 수 없습니다.

- Runtime: [Digilent Adept Runtime](https://digilent.com/reference/software/adept/runtime-previous-versions) — `digilent.adept.runtime_*.deb`
- Utilities: [Digilent Adept Utilities](https://digilent.com/reference/software/adept/utilities-previous-versions) — `digilent.adept.utilities_*.deb`

```bash
# 내려받은 .deb 패키지 설치 → 부족한 의존성 자동 보완
cd ~/Downloads
sudo dpkg -i digilent.adept.runtime_*.deb
sudo apt -f install

# 확인용 유틸리티(djtgcfg 포함) 설치
sudo dpkg -i digilent.adept.utilities_*.deb
sudo apt -f install

# 설치 확인: 경로가 출력되면 정상
which djtgcfg
```

| 명령 요소 | 의미 |
|---|---|
| `sudo` | 관리자 권한으로 실행 |
| `dpkg -i` | Debian 패키지 설치(`-i` = install) |
| `*.deb` | 이름이 맞는 파일 자동 선택 |
| `apt -f install` | 깨진 의존성 수정(`-f` = fix broken), `dpkg` 오류 뒤 실행 |

Adept 구성 요소는 다음과 같이 나뉩니다.

| 구성 요소 | 역할 |
|---|---|
| **Runtime** | USB 드라이버, 보드 인식 담당 — 가장 중요 |
| Utilities | 데이터 전송·테스트·디버깅 도구(`djtgcfg`) |
| SDK | C/C++로 보드를 제어하는 API |
| System | 구버전 GUI 도구, 현재 지원 종료 |

**③ 사용자 권한 설정**

```bash
# 시리얼(dialout)·USB(plugdev) 장치 접근 권한 부여 후 재부팅
sudo usermod -aG dialout $USER
sudo usermod -aG plugdev $USER
sudo reboot
```

**④ 최종 인식 확인**

```bash
# USB 장치 목록 → Digilent 보드 검색
lsusb
djtgcfg enum
```

예상 출력:

```text
Found 1 device(s)
Device: Basys3
```

| 증상 | 원인 | 해결 |
|---|---|---|
| `command not found` | Adept Runtime·Utilities 미설치 | ② 다시 수행 |
| `Found 0 device(s)` | USB 연결 문제 | 통신용 케이블·다른 포트·보드 전원 확인 |
| `Permission denied` | 권한 부족 | ③ 수행 후 재부팅, 급하면 `sudo` |

문제가 생기면 `lsusb` → `djtgcfg enum` → `groups` → `which vivado` → 오류 메시지 순으로 확인합니다. **보드가 보이지 않으면 드라이버부터 의심**하는 습관이 가장 빠른 해결책입니다.

## VS Code와 Vivado 역할 분리

| 작업 | VS Code | Vivado |
|---|:---:|:---:|
| Verilog·XDC·Tcl 작성, 대량 수정·검색 | ✅ | 가능하지만 불편 |
| 시뮬레이션 | 제한적 | ✅ |
| RTL Analysis · Synthesis · Implementation | ❌ | ✅ |
| Bitstream 생성 · FPGA 다운로드 | ❌ | ✅ |

**권장 작업 순서**

1. 터미널에서 프로젝트 폴더 생성
2. VS Code에서 Verilog(`rtl/`)·XDC(`constraints/`) 작성
3. Vivado에서 프로젝트 생성 → **Add Sources**로 RTL·XDC 등록
4. Run Simulation → Run Synthesis → Open Elaborated Design
5. Run Implementation → Generate Bitstream → Open Hardware Manager

| 상황 | Vivado 반영 |
|---|---|
| 등록된 파일을 VS Code에서 수정·저장 | 자동 반영 |
| VS Code에서 새 파일만 생성 | 반영 안 됨 → Add Sources 필요 |
| 파일 이름 변경·이동 | 연결이 끊길 수 있음 → Sources에서 다시 연결 |
| XDC 수정 | 저장 후 Synthesis·Implementation 재실행 |

> **기억할 점:** VS Code는 코드를 편하게 쓰는 도구, Vivado는 실제로 FPGA 회로를 만드는 도구입니다. **저장해야 Vivado가 읽고, 새 파일은 Vivado에 알려 줘야 합니다.**

## Basys3 하드웨어 개요

Basys3는 AMD Artix-7 `XC7A35T-1CPG236C`를 탑재한 입문용 디지털 회로 개발 보드입니다. 회로도와 상세 사양은 [Digilent Basys3 참조 설명서](https://digilent.com/reference/programmable-logic/basys-3/reference-manual)에서 확인합니다.

| FPGA 자원 | 사양 |
|---|---|
| 로직 셀 | 33,280개 (슬라이스 5,200개, 슬라이스당 6입력 LUT 4개 + 플립플롭 8개) |
| 블록 RAM | 1,800Kbit |
| 클록 관리 타일 | 5개 (각각 PLL 포함) |
| DSP 슬라이스 | 90개 |
| 기타 | 온칩 ADC(XADC) |

| 보드 주변 장치 | 수량·내용 |
|---|---|
| 슬라이드 스위치 | 16개 (위치에 따라 HIGH/LOW 유지) |
| 푸시 버튼 | 5개 (누를 때만 HIGH) |
| LED | 16개 (FPGA 핀이 HIGH일 때 켜짐) |
| 7세그먼트 | 4자리, 공통 애노드 |
| 기타 | Pmod 3개 + XADC용 Pmod, 12비트 VGA, USB-UART, USB HID 호스트, 32Mbit Quad SPI 플래시 |

**전원과 구성(Configuration)**

- 전원은 USB-JTAG 포트(J4) 또는 외부 5V 전원(J6)에서 공급하고, 점퍼 JP2로 선택합니다. 전원 스위치는 SW16, 전원 상태 LED는 LD20입니다.
- FPGA는 전원이 들어온 뒤 **비트스트림(`.bit`)** 으로 구성되어야 동작합니다. 구성 데이터는 FPGA 내부 SRAM에 저장되므로 전원을 끄면 사라집니다.

| 구성 방법 | 특징 |
|---|---|
| JTAG (J4, PROG) | Vivado Hardware Manager로 즉시 다운로드, 약 5초 |
| Quad SPI 플래시 | 전원을 켤 때 자동 구성, 기록 1~2분 |
| USB 메모리 (J2) | FAT32 루트에 `.bit` 하나, JP1을 USB로 설정 |

프로그래밍이 끝나면 **DONE** LED가 켜집니다.

**클록과 7세그먼트**

- 100MHz 발진기가 **W5** 핀에 연결되어 있습니다.
- 7세그먼트는 4자리가 세그먼트 신호(CA~CG, DP)를 공유하고 자리 선택(AN0~AN3)으로 구분하는 **다중화(Multiplexing)** 구조입니다. AN과 세그먼트 모두 **LOW일 때 켜집니다(Active Low).**
- 네 자리를 1~16ms 주기(약 60Hz~1kHz)로 번갈아 켜면 사람 눈에는 모두 켜진 것처럼 보입니다. 약 45Hz 이하로 느려지면 깜빡임이 보입니다.

## XDC 핀 제약 파일

XDC(Xilinx Design Constraints)는 **Verilog 포트를 보드의 실제 핀에 연결하고 클록 같은 동작 조건을 정의하는 파일**입니다. HDL 코드는 FPGA 내부 논리만 정의하므로 외부 연결은 XDC가 맡습니다. 과거의 UCF 형식을 대신하며, Vivado는 Tcl 문법 기반의 XDC만 사용합니다.

| 역할 | 예 |
|---|---|
| 핀 할당 (Pin Assignment) | 스위치 → FPGA 입력 핀, LED → FPGA 출력 핀 |
| 타이밍 제약 (Timing Constraint) | 클록 주파수 정의, Setup/Hold 조건 만족 유도 |

파일명: `basys3.xdc`

```tcl
## SW0 입력
set_property PACKAGE_PIN V17 [get_ports {sw[0]}]
set_property IOSTANDARD LVCMOS33 [get_ports {sw[0]}]

## LED0 출력
set_property PACKAGE_PIN U16 [get_ports {led[0]}]
set_property IOSTANDARD LVCMOS33 [get_ports {led[0]}]

## 100MHz 시스템 클록 (주기 10ns)
set_property PACKAGE_PIN W5 [get_ports clk]
set_property IOSTANDARD LVCMOS33 [get_ports clk]
create_clock -period 10.000 -name sys_clk [get_ports clk]
```

| 키워드 | 의미 |
|---|---|
| `PACKAGE_PIN` | FPGA 물리 핀 위치 |
| `IOSTANDARD LVCMOS33` | 3.3V CMOS 전압 규격 |
| `get_ports` | Verilog 포트 이름 |
| `create_clock -period 10.000` | 10ns 주기 = 100MHz |

**Basys3 자주 쓰는 핀**

| 장치 | 핀 |
|---|---|
| CLK 100MHz | W5 |
| SW0~SW7 | V17, V16, W16, W17, W15, V15, W14, W13 |
| SW8~SW15 | V2, T3, T2, R3, W2, U1, T1, R2 |
| LED0~LED7 | U16, E19, U19, V19, W18, U15, U14, V14 |
| LED8~LED15 | V13, V3, W3, U3, P3, N3, P1, L1 |
| BTNC / BTNU / BTNL / BTNR / BTND | U18 / T18 / W19 / T17 / U17 |
| 세그먼트 CA~CG, DP | W7, W6, U8, V8, U5, V5, U7, V7 |
| AN0~AN3 | U2, U4, V4, W4 |

스위치·LED·7세그먼트처럼 보드에 고정된 장치는 핀을 임의로 바꿀 수 없습니다. 항상 Digilent **Master XDC**를 기준으로 필요한 줄의 주석을 풀어 사용합니다.

| 자주 나는 오류 | 결과 |
|---|---|
| 핀 지정 누락 | Implementation 실패 (Unconstrained Port) |
| 핀 중복 | DRC 오류 |
| IO 규격 불일치 | 보드 손상 가능 |

## 첫 실습 SW0으로 LED0 제어

스위치를 올리면 LED가 켜지고, 내리면 꺼지는 가장 작은 회로입니다.

```text
SW0 입력 → FPGA 내부 논리 → LED0 출력
SW0 = 1 → LED0 = 1
SW0 = 0 → LED0 = 0
```

**① 프로젝트 생성**

1. `vivado` 실행 → **Create Project**
2. Project Name `sw_led_project`, 위치는 `~/viva_work`
3. **RTL Project** 선택
4. Boards 탭에서 **Basys3** 선택 (또는 Parts에서 `xc7a35tcpg236-1`)

**② Verilog 작성** — Add Sources → Add or Create Design Sources

파일명: `sw_led.v`

```verilog
module sw_led(
    input  wire sw0,    // 스위치 입력
    output wire led0    // LED 출력
);

    // 입력을 그대로 출력으로 연결
    assign led0 = sw0;

endmodule
```

| 구문 | 의미 |
|---|---|
| `module sw_led( ... );` | 회로 블록의 시작과 포트 목록 |
| `input wire sw0` | 외부 스위치에서 FPGA 내부로 들어오는 신호 |
| `output wire led0` | FPGA에서 외부 LED로 나가는 신호 |
| `assign led0 = sw0;` | 연속 할당, 입력 값을 그대로 출력에 연결 |
| `endmodule` | 모듈 끝 |

**③ XDC 작성** — Add Sources → Add or Create Constraints

파일명: `sw_led.xdc`

```tcl
set_property PACKAGE_PIN V17 [get_ports sw0]
set_property IOSTANDARD LVCMOS33 [get_ports sw0]
set_property PACKAGE_PIN U16 [get_ports led0]
set_property IOSTANDARD LVCMOS33 [get_ports led0]
```

**④ 합성 → 구현 → 비트스트림 → 다운로드**

| 단계 | Flow Navigator | 의미 |
|---|---|---|
| Synthesis | Run Synthesis | Verilog 코드 → 논리 게이트 회로 변환 |
| Implementation | Run Implementation | FPGA 내부 배치(Place)와 배선(Route) |
| Bitstream | Generate Bitstream | FPGA 설정 파일 `.bit` 생성 |
| Program | Open Hardware Manager → Open Target → Auto Connect → Program Device | 보드에 다운로드 |

**⑤ 동작 확인**

| SW0 | LED0 |
|---|---|
| OFF (아래) | OFF |
| ON (위) | ON |

이 회로는 `LED0 = SW0`, 즉 **버퍼(Buffer)** 와 같은 동작입니다.

| 오류 | 원인 | 해결 |
|---|---|---|
| 포트 이름 불일치 | `sw0`과 `SW0`은 다른 이름 | Verilog와 XDC 이름을 똑같이 |
| Unconstrained Port | XDC 핀 누락 | 모든 포트에 핀 지정 |
| 보드 연결 실패 | 케이블·전원·Runtime | 드라이버와 보드 인식 절 다시 확인 |
